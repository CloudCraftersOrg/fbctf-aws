# discovery_tool_export.zip — the real AWS Transform discovery tool output

Generated by the discovery collector (`environments/discovery-collector`) running
the actual AWS Transform discovery tool against the live estate: 6 synthetic
fleet hosts + the 3-app stack + both database engines, over **SSH (Linux)** and
**WinRM (Windows)** plus the **Oracle (:1521)** and **SQL Server (WinRM)**
database modules.

Upload `discovery_tool_export.zip` to the migration assessment as the discovered
data source.

## What it covers

| App / component | Host | How discovered | In the export |
|---|---|---|---|
| Contoso Scoreboard (.NET / IIS) | `fbctf-sqlmod-app` `10.40.0.125` | WinRM | inventory, processes (`w3wp`), net |
| Project Nami (WordPress / PHP) | `fbctf-sqlmod-wordpress` `10.40.0.108` | SSH | inventory, processes (`apache2`, `php`) |
| Contoso Catalog (Java / Spring) | `fbctf-oramod-app` `10.50.0.232` | SSH | inventory, processes (`java`), **dependency edge → Oracle :1521** |
| **SQL Server 2022** | `10.70.1.51` (synthetic) | WinRM SQL module | `sql_server_data_full.csv` — edition, version, binary/data paths, service account |
| **Oracle 21c XE** | `fbctf-oramod-oracle` `10.50.10.208` | Oracle :1521 (`transform_ro`/`XEPDB1`) | `oracle_data_cdbs/pdbs/components/options` — CDB `XE` 21.3, PDB `XEPDB1`, 30 schemas, NOARCHIVELOG, AL32UTF8 |
| Synthetic fleet | `10.70.1.21-41` | SSH | inventory + perf + processes per role |

## Files

- `full_exports/` — full-fidelity CSVs: `server_inventory`, `server_performance_metrics`,
  `server_storage_performance`, `storage_config`, `network_interfaces`,
  `network_data_full`, `process_metrics` (~1700 rows), `sql_server_data_full`,
  `oracle_data_*`
- `mpa_exports/` — the same reduced to the Migration Portfolio Assessment schema
  (`network_data_mpa` carries the app→DB dependency edges)

The metric collectors sample continuously; this snapshot is a ~1 h window. Re-run
the export from the collector for a longer window.
